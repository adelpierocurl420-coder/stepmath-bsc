# FestDesk

*Smart club operations for student organizations: browse fests, register for events, and manage everything from one organizer dashboard.*

Built for the **9th DRMC International Tech Carnival 2026 — AI Web Development Contest** · Theme: Smart Club Operations · Hierarchy: **Organization → Fest → Event → Registration**

## 1. Project name

**FestDesk**

## 2. Project description

Student clubs often collect event registrations with Google Forms, which gives no seat limits, no deadlines, no waitlist and no organizer tools. FestDesk replaces that with one platform. One organization (sample: **DRMC IT Club**) hosts several fests, each fest has several events, and people register for individual events. Participants see seats and deadlines before registering, get a ticket, and can edit or cancel later. Organizers get a dashboard with participants, status control, statistics and check-in.

## 3. Features

**Fest directory**
- Fests with dates, venue and open-event counts; fest detail page listing its events
- Event cards: title, fest, category, date and time, venue, deadline, seat bar and seats left
- Search, category filter, fest filter, "open only" toggle
- Event page: description, venue, deadline, capacity, registration information, announcement
- Responsive layout for phone, tablet and desktop, light and dark theme

**Registration**
- Validated form (name, email, phone, institution, optional notes) with clear errors
- Confirmation ticket with unique REG ID and QR code, printable
- Capacity and deadline enforced in code; duplicate email per event blocked
- **My Registrations**: look up by email, view ticket, edit details, cancel (frees the seat)
- Instant confirmation or organizer approval, set per event

**Organizer**
- Login (demo credentials below); the session persists in `localStorage`, so it works on phones
- Overview: KPIs, status breakdown, per-event fill bars, registrations in the last 7 days
- Participants: search by name, email, phone or ID; filter by event and status; change status (pending, confirmed, waitlist, rejected, cancelled); remove; CSV export
- Create, edit and delete fests and events
- Check-in by REG ID or email

**Bonus**
- Waitlist when an event is full, with automatic promotion (oldest first) when a seat opens by cancel, reject, removal or a capacity increase
- QR code on the ticket and organizer check-in
- 7-day registrations chart
- Live countdown to the deadline and event start
- Optional announcement per event
- Seeded demo data: 3 fests, 10 events, 400+ registrations, a closed event, a nearly full event and a full event with a waitlist

## 4. Tech stack

- HTML, CSS and vanilla JavaScript in a single file (`index.html`); no framework, no build tooling
- Hash routing: `#/`, `#/fest/:id`, `#/event/:id`, `#/my`, `#/admin`
- Browser `localStorage` for data and the organizer session
- Netlify static hosting (`dist/` is a copy of `index.html`)

## 5. Setup instructions

```bash
git clone <repo-url>
cd <repo>
python3 -m http.server 8000     # then open http://localhost:8000
# or simply open index.html in a browser
```

Deploy on Netlify: build command `npm run build`, publish directory `dist` (already set in `netlify.toml`). Sample data is created on first load with dates relative to that day. **Organizer → Reset demo data** restores it.

## 11. Known limitations

- Data lives in each browser's `localStorage`. Registrations are **not shared between devices or people**; there is no cloud database.
- Organizer login is a demo check in the browser, not production security.
- QR codes need internet access to the QR image service.
- Check-in is typed (REG ID or email); there is no camera scanning.
- No emails or SMS are sent.
- Waitlist promotion happens in the browser that holds the data.
